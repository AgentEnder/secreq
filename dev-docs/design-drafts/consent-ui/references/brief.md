# Brief: secreq consent UI restyle

> Generated by `design-drafts:brief` on 2026-07-09. Edits welcome — keep the section headings stable so consuming skills can parse it.

## Audience

- **Who:** Primarily the author ("it's mostly for me"), a developer running AI agents and CLIs that request secrets. Secondarily: other developers adopting secreq — "other devs adopting it should trust it and I want it to be semi-marketable." The consent window is the trust surface and the README screenshot; its look is part of the security argument.
- **Currently using:** The existing egui consent window, which "looks super LLM and is a bit less sleek than I'd prefer." (Outside secreq: raw env vars and per-tool credential prompts.)
- **What they care about:** A tool that brokers secrets must look deliberate. "It should feel like a desktop app, and look like a desktop app, not like an AI-designed web app."

## Intent

- **Primary action:** Pick — review the draft grid and choose the one visual direction that gets ported to the egui implementation.
- **Primary outcome:** One committed direction (theme + decision-surface), with the runner-up mined for parts.
- **Secondary action:** Harvest specific components from non-winning pages (a column layout, a confirm interaction) even if their overall direction loses.

## Constraints

- **Palette:** Theme-dependent; neither theme is inherently dark. **Terminal Ledger**: palettes work like terminal color schemes — the structure (mono, columns, hairline rules) is the identity and the scheme is swappable; drafts show one representative dark terminal palette. **Native Sentinel**: system-neutral grays that follow OS appearance; drafts show it in **both light and dark**, since appearance-following is its core claim. Banned: the current GitHub-dark ground + blue accent + green/red fills.
- **Typography:** Theme-implied — Ledger is monospace everywhere; Sentinel uses system-UI faces with mono reserved strictly for commands, paths, and secret names. Exact families: `TBD — open question`.
- **Layout shape:** Committed: **two-window Prompt + Manager split** (Little Snitch shape). The consent prompt is a small transient panel; Rules and Audit live in a separate manager window. The prompt carries an affordance to open the manager — for the "this ask should've been auto-approved" moment, landing near rule creation. Within the manager: Audit = **Manifest Rows** (scannable table, real columns), Rules = **Grouped Inset** (System-Settings-style grouped list).
- **Density:** Per-page, not global. Prompt = **Focus Stack**: one ask at a time, rendered like a 1Password/UAC prompt, queue as "2 more waiting" text. Audit = dense table. Rules = grouped list. Rationale: "the main ask resolution matches the focus stack the best, while the audit log and auto-approval configuration pages don't really lend that direction."
- **Must include:** Every prompt draft must show, or the comparison is dishonest:
  - the process ancestry as a tree with argv per process (e.g. Superset.app → zsh → gh, each with its command line), so the asking process is identifiable
  - the secret name + provider URI pair (e.g. `GITHUB_TOKEN` / `op://Personal/GitHub/credential`)
  - the "first request from this caller" provenance hint
  - a pending-count indicator
  - the prompt→manager affordance

### Draft grid (revised after first-round review, 2026-07-09)

First round settled the theme: **Terminal Ledger is eliminated; Native Sentinel wins** — its manager pages were approved as-is, but the prompt "could use some work," and single-flavor Sentinel "will look great on macOS but really out of place on Linux and Windows."

Current axes: **page** (prompt / audit / rules) × **os** (macos / windows / linux-GNOME) × **appearance** (light / dark). Each OS renders its native dialog and window idiom, not a reskin: macOS alert panel, Windows 11 ContentDialog (equal-width footer buttons, Segoe, 4px radii), GNOME AdwMessageDialog (centered heading, full-width hairline-separated button row, suggested-action accent). Linux means GNOME/libadwaita specifically.

**Decision surface: committed, no longer an axis.** Native button pairs with the hotkey shown as an underlined mnemonic character in the label (Approve/Deny with underlined A/D). Keyboard-first and asymmetric-friction retired.

**Prompt rework requirements from review:** tighten proportions and spacing; give the provenance block real structure (an inset well, not a loose grid); and render the caller as a **process tree with argv per process** — "right now it's hard to identify which process is asking for something since you can't see argv." The argv-bearing tree is a must-include on every prompt page.

## Reference inspiration

See `references/links.md` and `references/inspiration/` for the source material.

- Little Snitch — the two-window shape (transient connection alert vs. separate rule editor) and the matter-of-fact microcopy register.
- 1Password — the unlock prompt as Focus Stack: one decision, rendered big, answered and gone.
- k9s — Terminal Ledger's lineage: a serious TUI with column grids, key-glyph affordances, and swappable skins.
- Native OS touchstones without URLs (cited from the explore session): Activity Monitor (Manifest Rows), macOS System Settings (Grouped Inset), Keychain prompts (Sentinel's kinship), man pages (voice).

## Must-not-look-likes

Cited by entry number from the anti-pattern catalog:

- **#2 — Glassmorphism plus neon glow on dark mode:** the current UI's family (GitHub-dark, rounded 1px-bordered cards, blue accent) is exactly the "Linear-imitator" median being replaced.
- **#7 — Identical pill CTAs everywhere:** today's six green/red filled pills across three tree levels are the single loudest tell; Dialog Buttons demands exactly one default-highlighted pair, Keyboard-First removes buttons entirely.
- Colored status pills as labels (`approved •`, `2 pending •`) — status should read as a record or an indicator, not a web badge.
- Cards floating on a void — nothing on any page is a free-floating rounded card.
- Web-app top tabs — the committed layout removes them.
- "AI sloppy text" in any copy — filler adjectives, dramatic em-dash pauses (#23), exclamation marks, emoji.

Defaults the user is consciously embracing (do not flag in review):

- **Native OS idioms as-is:** default-highlighted dialog buttons, disclosure triangles, system grays — these are deliberate borrowings from OS chrome, not unexamined defaults.

## Voice

- **Adjectives:** terse — like man pages; matter-of-fact — like Little Snitch. (Two adjectives given and defended; no third was offered and none is invented here.)
- **Off-limits vocabulary:** cuteness of any kind, emoji, "AI sloppy text" (filler adjectives, hype words, dramatic punctuation). No security theater ("military-grade").
- **Reference copy:** the existing Rules-tab explainer, kept as the benchmark register: "Rules fire before the consent prompt. Deny rules win; most-specific approve wins ties."
